# Chatra Backend

Бэкенд образовательной платформы Chatra: классы, потоки, задания,
ИИ-оценивание и файлы — одним сервисом.

**Python 3.14 · FastAPI · SQLAlchemy 2.0 · PostgreSQL · OpenAI**

---

## Быстрый старт

Три команды до работающего сервера.

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --reload-exclude venv --host 0.0.0.0 --port 8000
```

- Документация API — <http://localhost:8000/docs>
- Проверка живости — <http://localhost:8000/health>

Перед первым запуском нужен `.env` — см. следующий раздел. На чистой базе
схема создаётся сама: миграции не нужны.

> Установка тянет torch и easyocr, поэтому первый `pip install` небыстрый.

## Конфигурация

Скопируйте `.env.example` в `.env` и заполните. Обязательный минимум:

```env
OPENAI_API_KEY=sk-proj-...
SECRET_KEY=<openssl rand -hex 32>
REFRESH_SECRET_KEY=<openssl rand -hex 32>   # другое значение
DATABASE_URL=sqlite:///./chatra.db          # или postgresql://...
APP_BASE_URL=http://localhost:8000
```

Без `SECRET_KEY` и `REFRESH_SECRET_KEY` сервер не стартует — это намеренно.

| Группа | Переменные | Если не задано |
|---|---|---|
| База и сеть | `DATABASE_URL`, `APP_BASE_URL`, `CORS_ORIGINS` | SQLite, `localhost:8000`, `*` |
| Хранилище | `R2_*` (Cloudflare R2), `UPLOAD_DIR`, `FILE_URL_TTL` | локальная папка `uploads/` |
| Почта | `SMTP_*` | коды подтверждения пишутся в лог |
| Push | `FCM_SERVICE_ACCOUNT_*` | уведомления не отправляются |
| ИИ | `CHAT_MODEL`, `EMBED_MODEL`, `AI_DAILY_*`, `COVER_IMAGE_*` | разумные значения по умолчанию |
| Масштаб | `REDIS_URL`, `DB_POOL_*` | лимитер и пул — в пределах процесса |

Полный список с комментариями — в `.env.example`.

## База данных

**Новая база.** Запустите сервер — таблицы создадутся при старте.

**Существующая база.** Проект использует не Alembic, а пронумерованные файлы
в `migrations/`: `.sql` применяются через `psql`, `.py` — напрямую
интерпретатором и сразу по обеим организациям (university и school).
Python-миграции идемпотентны, повторный запуск безопасен.

```bash
DATABASE_URL="postgresql://user:pass@localhost:5432/chatra" \
  ./venv/bin/python migrations/009_backfill_cohorts.py
```

`DATABASE_URL` передаётся явно: миграции запускаются вне приложения и `.env`
не читают.

Применяйте по возрастанию номера то, чего ещё нет в вашей базе:

| # | Что добавляет |
|---|---|
| 002–004 | pgvector для RAG, изоляция по `org_type` |
| 005–007 | инвайт-коды, перенос постов в классы, поля сообщений |
| **009** | учебные потоки: `cohorts`, `deadlines`, `rotation_mode` |
| 014–015 | миниатюры обложек и пересжатие существующих |
| 016–020 | чистка снятых фич, позиция лекции, RAG-индекс лекций |
| **021–022** | оформление обложек, дата регистрации пользователя |
| — | `add_user_blocks.py`, `add_reports.py` — модерация UGC |

Девятая — ключевая: без неё эндпоинты классов не работают.

## Доступ с других устройств

Приложение по умолчанию ходит на `localhost:8000`, поэтому телефону нужен
другой адрес.

**По локальной сети.** Узнайте IP (`ipconfig getifaddr en0`), запустите сервер
с `--host 0.0.0.0` и укажите этот адрес в `defaultBaseUrl` приложения и в
`APP_BASE_URL`. Android-эмулятор вместо IP использует `10.0.2.2`,
iOS-симулятор — обычный `localhost`.

**Через туннель.** Так поднят прод:

```bash
ngrok http --domain=glacier-radiated-wipe.ngrok-free.dev 8000
```

Ссылки на файлы приложение переписывает под текущий адрес само.

Для продакшена — без `--reload`:

```bash
nohup ./venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000 > uvicorn.log 2>&1 &
```

## Возможности

### Классы и потоки

Класс — это предмет, который живёт годами. Состав и дедлайны принадлежат не
классу, а потоку (`cohorts`): новый учебный год открывается новым потоком, а
материалы, задания и история остаются на месте. Данные школ и вузов разделены
на уровне запросов.

### Задания и ИИ-оценивание

Работы принимаются файлами и текстом, разбираются парсерами (PDF, DOCX,
изображения с OCR) и оцениваются моделью с оценкой уверенности: спорное
уходит преподавателю. Лимиты — дневной бюджет токенов на организацию и лимит
сообщений на пользователя.

### Обложки предметов

Преподаватель выбирает цвет и символ — обложку рисует бэкенд, одинаковую для
веба и приложения. Все обложки принадлежат одной коллекции: тёмный градиент,
мягкое свечение, тонкая графика по теме предмета. Символ накладывают клиенты
поверх картинки, поэтому он всегда чёткий.

Генерация идёт только по явному нажатию и стоит около шести центов. Любой сбой
— нет ключа, таймаут, исчерпан бюджет — деградирует к локальному фолбэку в том
же стиле: предмет никогда не остаётся без обложки. Старые загруженные вручную
обложки продолжают работать как прежде.

Настройка — `COVER_IMAGE_*`, реализация — `services/cover_art.py`, отчёт о
расходе — `GET /admin/ai-usage/covers`.

### Файлы

Новые файлы хранятся в Cloudflare R2, разложенные по категориям
(`attachments/`, `submissions/`, `assignments/`, `materials/`). Имя файла в
ключе — оригинальное, поэтому при скачивании пользователь видит понятное
название.

Отдаются файлы через один защищённый эндпоинт `/uploads/...` с HMAC-подписью:
публичного доступа к бакету нет, ссылка выдаётся вместе с ресурсом, на который
есть права. Исключение — обложки классов: они не приватны и при заданном
`R2_PUBLIC_BASE_URL` идут напрямую с CDN. Картинки сжимаются в WebP и получают
миниатюру для списков.

Файлы, загруженные до подключения R2, остаются в `uploads/` и отдаются как
раньше.

### Модерация

Жалоба, блокировка и реакция модератора в течение суток — требование App Store
и Google Play. Блокировка взаимна по видимости и работает на сервере: контент
исключается из выдачи, прямые ссылки отвечают 404, push не доходит.

| Метод | Путь | Роль |
|---|---|---|
| POST | `/api/reports` | любой |
| POST · DELETE | `/api/users/{id}/block` | любой |
| GET | `/api/users/blocked` | любой |
| GET | `/api/admin/reports?open=true` | админ |
| POST | `/api/admin/reports/{id}/resolve` | админ |

## Структура

```
main.py           точка входа, FastAPI app, создание таблиц
models.py         SQLAlchemy модели
schemas.py        Pydantic схемы
db.py             подключение к базе
deps.py           зависимости: сессия, текущий пользователь, роли
security.py       JWT
permissions.py    правила доступа к классам, заданиям, работам
routers/          эндпоинты: auth, users, classes, cohorts, ai, …
crud/             операции с базой
services/         бизнес-логика: оценивание, обложки, лимиты, хранилище
parsers/          разбор файлов: PDF, DOCX, OCR
migrations/       SQL и Python миграции
uploads/          файлы до подключения R2 (legacy)
tests/            pytest
```

```bash
./venv/bin/pytest
```
